# 开源说明

## 项目是什么

OpenShop（开集）是一个**可自托管、可审阅的电商参考实现**。目标不是伪装成一个已规模化运营的平台，而是把多边供给、服务端权威计价、模拟支付、订单/售后与商家操作做成可阅读、可运行、可检查的代码。

当前状态是 v0.1.2 本地源码验收版：真实 API/浏览器、三轮并发、44/44 独立安全探针（39/39 controls）、标准库测试与仓库门已在本地通过。项目未公开部署、未 push 远端，也没有通过外部生产容量、性能或公网渗透审计。OpenShop 不声称与任何现有电商平台存在关联、授权或背书。

## 内容与素材来源

- 商品、品牌、店铺、人物、头像、评价、订单和所有演示数据均为**虚构**或由项目编写，不对应真实个人、公司或交易。
- 商品图、图标和品牌标记是仓库内原创 SVG；不包含真实平台 Logo、UI 截图、商品照片、外部字体或不明确许可的素材。
- 文档可能把公开研究过的电商交互模式（自营、品牌店、拼团等）作为设计参照，但不复制第三方商标、页面或文案。所有引用仅为说明产品模式。
- 请不要向演示环境导入真实个人数据、支付信息、凭据或受版权保护的第三方内容。

## 运行时依赖政策

- 后端运行时只用 Python 标准库与 SQLite。
- 前端是原生 ES Module + 本地 CSS/SVG，无构建步骤、无 npm 运行时依赖、无外部 CDN、远程字体或分析脚本。
- 仓库门会检查 HTML/CSS/JS/JSON 的外部资源引用、裸 JS import、Python 运行时第三方 import 和 package.json 依赖声明。它是辅助门槛，不是供应链安全的全部证明。
- Node 仅作为开发/CI 中检查 JavaScript 语法的本机工具，不是产品运行依赖。CI 平台本身及其官方 checkout 动作属于构建基础设施，不被打包进运行时。

## 可审阅性与证据

- 冻结的接口与数据约定在 [docs/api-contract.md](api-contract.md)、[docs/data-contract.md](data-contract.md)。
- CI 仅授予 contents: read，禁用持久化 checkout 凭据，不安装外部包。
- 当前 workflow 通过官方 checkout action 的发行标签引用外部动作；仓库门会报告 tag-pinned 警告。把它作为已知供应链边界记录，正式生产化前应固定到已审阅提交摘要并复跑门禁，不能隐藏该警告。
- [tools/check_repository.py](../tools/check_repository.py) 提供 fail-closed 的仓库检查与带正/负控的 `--selftest`；[.github/workflows/ci.yml](../.github/workflows/ci.yml) 会运行标准库测试、门禁自检与当前树门禁。
- “通过”只以当前提交上的现跑输出为准。历史截图、口头声明或一次本地启动不能代替测试和门禁。未完成树上的门禁失败必须保留并修复，不能通过放宽规则消除。
- 固定发布应绑定提交、归档 SHA-256 和验收证据；当前流程见 [docs/RELEASE.md](RELEASE.md)。本准备任务没有创建标签、发布制品或部署。

## 明确限制

OpenShop 是**非生产级**演示：

- 支付为模拟，不代表真实资金流；没有真实物流、KYC/身份、税务、风控或合规流程。
- 单进程 HTTP 服务 + SQLite 是刻意选择的可审阅架构，不代表高可用或横向扩展能力；未做生产压测。
- 仓库内 systemd/Caddy/DNS/证书相关内容只到模板与非执行文档边界；生产入口和发布需要单独授权。
- 不承诺数据库版本间的自动迁移或无损回滚；升级前必须备份并验证兼容性。
- 没有经过第三方安全审计、法律审查或可用性认证。

这些问题在文档和发布检查中应持续保留，不能被营销文案替代。
