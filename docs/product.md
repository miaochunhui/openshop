# OpenShop 产品定义

## 一句话

一个把“自营的可信、旗舰店的丰富、源头拼团的划算”放在同一商品页上比较、购买与售后的开源电商平台。

## 目标用户

1. **买方**：想在一个地方比较不同供给、看清为什么值这个价、不被打扰地完成购买并追踪售后。
2. **商家**：要管理自己店铺的报价、库存、发货和售后，不需要学习复杂后台。
3. **研究者 / 开发者**：需要一个零外部依赖、可读、可测、可改的真实电商参考实现。

## 对标能力（只作模式研究，不使用对方商标或素材）

| 平台模式 | OpenShop 的落地 |
| --- | --- |
| 淘宝：丰富供给、品牌旗舰、评价内容 | 多店商品目录、分类与搜索、品牌店铺页信息、可筛选评价 |
| 拼多多：拼团、源头直供、低价心智 | 真实拼团进度与邀请码、工厂供给报价、透明价差 |
| 京东：自营、品质、履约确定性 | 自营标签、配送时效、包裹发货/物流时间线、7 天无理由 |

## 三条不能破的产品底线

1. **真实**：倒计时、拼团人数、库存、销量不造假；无法完成的状态必须明确说明。
2. **可解释**：同一商品的多供给必须显示价格、店铺、配送与服务差异，不用隐藏费用诱导。
3. **可撤销**：模拟支付可取消，优惠在取消后按规则退回，退款/评价状态可追踪。

## 买方旅程

- **发现**：首页活动、分类、搜索、筛选、排序、商品推荐、浏览记录。
- **判断**：图集、核心卖点、三供给比较、SKU、服务承诺、评价摘要与完整评价、规格与 FAQ。
- **购买**：游客购物车、登录/注册/一键演示、优惠券、地址簿、配送选择、服务端报价、模拟支付。
- **收尾**：订单列表与详情、包裹物流、取消、确认收货、发表评价、发起售后。
- **拼团**：从拼团报价进入结算，生成真实邀请码；第二人加入后满团；未满团倒计时到期可取消退款。

## 商家旅程

- 演示商家登录后查看经营概览、商品库存与价格、待发货订单、物流发货、售后请求。
- 商家只能操作自己店铺的数据；所有权限由服务端校验。

## 明确不做

- 真实支付、真实物流、真实身份/KYC、真实库存对外承诺。
- 秒杀压测、推荐模型训练、分布式事务、线上风控——它们是真实商业系统议题，但不在本次开源 MVP 中冒充已实现。
- 复制任何现有平台的页面、商标、商品图或文案。

## 验收体验切片

1. 桌面首页 -> 搜索“耳机” -> 筛选自营 -> 打开商品 -> 切换供给/SKU -> 加购。
2. 游客加购 -> 一键买家演示 -> 购物车 -> 选券 -> 新建地址 -> 结算 -> 模拟支付。
3. 换商家演示 -> 查看同一订单包裹 -> 填物流单号发货。
4. 换回买家 -> 确认收货 -> 写一条真实评价。
5. 首页发起/加入拼团 -> 查看满团状态；未满团不显示假成功。
6. 移动端完成搜索、加入购物车、账户页浏览；键盘可走通主路径。
